## Ustalenie kluczowe: przyczyna czerwonego CI

Błąd joba `flutter` wynika **wyłącznie** z braku `google-services.json` przy braku jawnej flagi:

```
Execution failed for task ':app:processDevDebugGoogleServices'
> File google-services.json is missing.
Gradle task assembleDevDebug failed with exit code 1
```

Kroki przed buildem (format, analiza, 136 testów) przeszły. To oczekiwany efekt SEC-33: `build.gradle.kts` nie honoruje już `CI=true`, a `ci.yml` na `main` (linia 99) to nadal `flutter build apk --debug` bez `-P tamitu.allowMissingGoogleServices=true`. GH-011 jest dodawany w tym PR (`.farm/requests/GH-011-…`), więc Steward może go wykonać dopiero po jego zobaczeniu; zmiana jest zgodna wstecz z `main`, bo obecny Gradle na `main` już honoruje tę właściwość. **W kodzie nie ma innej przyczyny błędu.** Pełny przegląd „po zielonym CI” – do potwierdzenia ponownym uruchomieniem (oczekiwane: `assembleDevDebug` z ostrzeżeniem zamiast błędu).

## Sprawdzone – zgodne (bez ustaleń)

- **Emulatory/cleartext tylko w dev debug:** `network_security_config_emulators.xml` i manifest w `android/app/src/devDebug/` – zestaw źródeł łączony tylko dla wariantu `devDebug`; `prodDebug`, `devRelease`, `prodRelease` i `profile` go nie dostają. `base-config cleartextTrafficPermitted="false"`, wyjątek tylko dla `10.0.2.2`, `127.0.0.1`, `localhost` (bez subdomen). Główny manifest bez zmian: `usesCleartextTraffic="false"`, brak własnego `networkSecurityConfig`, więc nie ma konfliktu scalania. `minSdk 26` – konfiguracja sieci działa na wszystkich wspieranych wersjach.
- **Strażnik w Dart:** `assertFirebaseEmulatorsAllowed` (`lib/app/environment.dart:460`) wywoływany w `bootstrap.dart` przed `connectFirebaseEmulators`, a test kolejności to sprawdza. Warunek używa `kDebugMode` (profile też odrzucony – ostrzejszy niż `TAMITU_FAKE_BACKEND`, słusznie). W buildzie prod/release bez `--dart-define` kod emulatorów jest martwy (stała `false`) i usuwany przez tree-shaking; z `--dart-define` aplikacja kończy start `StateError`.
- **Adapter logowania emulatora niedostępny w prod:** `EmulatorAuthGateway` tworzony tylko w `connectFirebaseEmulators`, osiągalnym wyłącznie przez gałąź `useFirebaseEmulators` po strażniku. Fałszywy token (niepodpisany JSON) przyjmuje tylko emulator Auth – prawdziwy Firebase Auth by go odrzucił. Nawet przy obecnym `google-services.json` aplikacja domyślna (`tamitu-dev-tadecode`) nie jest używana w trybie emulatorów: `grep` po `lib/` – jedyne użycia `FirebaseAuth.instance`/`FirebaseFunctions.instanceFor`/`FirebaseAppCheck.instance` bez nazwanej aplikacji są w gałęzi `else` (`bootstrap.dart:72,84`, `firebase_auth_gateway.dart:19`).
- **Sekrety:** brak `google-services.json` i kluczy w diffie (gitleaks ✅). Opcje `demo-api-key`/zerowe `appId` to stałe zastępcze. `APP_ID` w `android/FIREBASE.md` to publiczne identyfikatory (są w APK) i występują już na `main` (runbook P3-03, GH-009).
- **Dane osobowe:** e-mail testowy `<sub>@example.com` (domena zastrzeżona), `testSub` walidowany (`^[A-Za-z0-9_-]{1,64}$`, test odrzuca `a@b.pl`). Brak nowej kategorii danych – rejestr bez zmian (słusznie).
- **O4-1:** `backend/firestore.indexes.json` po zmianie jest identyczny (po normalizacji białych znaków) z blokiem JSON w `docs/data/schema/firestore-ttl-indexes.md` pkt 5. Kod backendu jeszcze nie zapisuje `usage/{uid}` (P3-05), więc wdrożenie polityki (O4-2) przed P3-05 niczego nie usunie; P3-05 musi ustawiać `expireAt` jako `Timestamp` (pkt 3.2 dokumentu).
- **OBS-1 a dane osobowe:** `logFailure` nadal przepuszcza wpis przez `sanitizeFields` (lista dozwolonych pól ADR-0002, przycięcie do 64 znaków); zmienia się tylko poziom. `errorClass === "AppError"` pochodzi z `classifyError` (stały literał, nie `constructor.name`), więc minifikacja go nie zepsuje. Wyjątek spoza kontraktu (także `FirebaseError` z kodem wyglądającym jak kontraktowy) → ERROR – pokryte testem.
- **PR #70 ust. 4 b/c:** `serviceAccountEmail()` nie ma innych użyć w `src/` ani skryptach (grep); `FIREBASE.md` zgodny z runbookiem etap 10.
