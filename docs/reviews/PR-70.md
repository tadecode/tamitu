## Podsumowanie
PR przypisuje każdej z czterech funkcji osobne konto usługi (`fn-ai-plan`, `fn-consent`, `fn-account`, `fn-budget`), uzupełnia aliasy `backend/.firebaserc` (domyślnie dev) i dodaje wtyczkę `com.google.gms.google-services` dla flavorów dev/prod bez commitowania `google-services.json`. Zmiana jest mała, czytelna i dobrze przetestowana; obejście braku pliku w CI jest bezpieczne (bez atrapy, bez wartości). Brak blokerów i ustaleń wysokich; dwa średnie dotyczą zakresu obejścia `CI=true` po GH-009 i kolejności względem ADR-0014.

## Wydajność
Bez wpływu: zmiana dotyczy wyłącznie metadanych wdrożenia (konto usługi) i konfiguracji buildu. `maxInstances`, pamięć i timeouty bez zmian. Wtyczka `google-services` działa tylko w czasie buildu.

## Zależności
`com.google.gms.google-services` 4.5.0 – przypięta wersja, repozytorium `google()` (`android/settings.gradle.kts:13-17`), zgodna z API `missingGoogleServicesStrategy` (≥ 4.4.0). `osv-scanner` nie uruchomiony; Dependabot obejmie wtyczkę jak pozostałe zależności Gradle.

## Czego nie sprawdzono
- Rzeczywiste wdrożenie funkcji z kontami `fn-*` (brak dostępu do projektów; zakaz uruchamiania kodu PR lokalnie) – efekt skrótu `@` potwierdzony tylko w kodzie Firebase CLI 15.36.0.
- Build z prawdziwym `google-services.json` i logowanie na urządzeniu (test P3-04 właściciela).
- Treść komunikatu WARN wtyczki w logu CI (log potwierdza tylko zbudowany APK).
- Wynik `npm run typecheck` – nadal nie ma go w CI (#51/4), znany z deklaracji autora.

## Propozycje do checklist (opcjonalnie)
- Obejścia kontroli buildu (brak pliku konfiguracyjnego, podpisu itp.) wiązać z jawną flagą lub typem buildu, nie z ogólną zmienną środowiska `CI` – inaczej przestają chronić build wydaniowy w CI.
